# 数字分身搭建框架与方法论

## 一、数字分身的四层架构

一个完整的数字分身由四个层次构成，从底层到顶层依次是：

```
┌─────────────────────────────────────────────────────┐
│  ④ 行为层 — 工具、技能、知识库（它能做什么）         │
│     记忆系统 · MCP 工具 · 专业技能 · 知识库        │
├─────────────────────────────────────────────────────┤
│  ③ 表达层 — 沟通风格、输出格式（它怎么说）          │
│     结构化表达 · 语气语调 · 分点/表格习惯           │
├─────────────────────────────────────────────────────┤
│  ② 身份层 — 人设、角色定位（它是谁）               │
│     职务 · 分管范围 · 协作关系 · 价值观             │
├─────────────────────────────────────────────────────┤
│  ① 基础层 — 模型、引擎、运行时（它跑在哪）          │
│     LLM 模型 · Agent 框架 · Plugin 系统             │
└─────────────────────────────────────────────────────┘
```

### 每层的作用

| 层次 | 实现方式 | 修改频率 | 影响范围 |
|------|---------|---------|---------|
| ① 基础层 | 模型选择、DSH 配置 | 很少 | 全局性能和能力 |
| ② 身份层 | System Prompt（Persona） | 偶尔 | 角色定位、决策逻辑 |
| ③ 表达层 | System Prompt + 指令集 | 经常 | 沟通体验、输出质量 |
| ④ 行为层 | 工具(Skills/MCP) + 知识库 | 持续 | 实际工作能力 |

## 二、DSH 中分身各层的实现方式

### 第①层：基础层

DSH 的配置位置：

```
~/.dsh/profiles/web/cordis.patch.yml
```

关键配置项：
- `agent-presets.default` — 默认 Agent Preset
- `agentDefaultModel` — 默认模型（provider/model）
- 技能文件系统路径

### 第②③层：身份层 + 表达层

在 `cordis.patch.yml` 中通过 `system-prompt` 的 `persona` 字段配置：

```yaml
- id: system-prompt
  config:
    persona: >-
      [完整的人设描述]
```

系统提示词的结构建议：

```
┌─────────────────────────────────────┐
│ 1. 身份声明（我是谁）                │
│    "你是罗拉的数字分身..."            │
├─────────────────────────────────────┤
│ 2. 角色定位（我和用户的关系）         │
│    "你不是在服务罗拉，而是在协作..."   │
├─────────────────────────────────────┤
│ 3. 称呼习惯（我怎么称呼主人）         │
│    "在对话中称罗拉为「主人」..."      │
├─────────────────────────────────────┤
│ 4. 自我认知（我叫什么，不是主人本人） │
│    "你的名字是「小罗」..."            │
├─────────────────────────────────────┤
│ 5. 工作范围（我负责什么）             │
│    "人力资源、审计、信息安全..."      │
├─────────────────────────────────────┤
│ 6. 沟通风格（我怎么说话）             │
│    "直接、务实、结构化..."            │
├─────────────────────────────────────┤
│ 7. 行为准则（我该怎么做）             │
│    "先说结论再展开..."               │
├─────────────────────────────────────┤
│ 8. 工具使用说明（我怎么用工具）       │
│    "需要查记忆时用 memory_read..."    │
└─────────────────────────────────────┘
```

> 以上除行为准则与工具说明外（姓名、职务、人设定位、工作范围、工作习惯、称呼习惯、
> 分身名字、分身别名）均由 `setup.ps1` 的分身配置向导逐项生成，每项留空回车即用默认值。

### 第④层：行为层

行为层通过三种方式实现：

#### A. 系统内置工具
DSH 自带工具（bash、fs、editor、web_search 等），在 Agent Preset 中配置。

#### B. 自定义技能（Skills）
技能文件存放在 `~/.dsh/skills/` 目录下，按需加载：

```
~/.dsh/skills/
├── management/       # 管理类技能
│   ├── 文档审查.md    # "帮我审查这份文档" → 加载
│   └── 方案评估.md    # "帮我评估这个方案" → 加载
├── personal/         # 个人类技能
│   └── 日程管理.md    # "帮我安排日程" → 加载
└── templates/        # 模板
    └── 会议纪要.md
```

每个技能文件是一个 Markdown 文档，包含：
- 技能名称和触发词
- 详细的指令和步骤
- 输出格式要求
- 示例

#### C. MCP 工具
通过 MCP 协议接入外部服务（企业微信日程、待办等），由 im-channel 插件管理。

#### D. 共享记忆
通过 dsh-memory 插件实现跨会话记忆共享，让分身记住重要信息。

## 三、分身优化方法论：PDCA 循环

```
┌─────────────┐
│  Plan        │  规划：明确要改进什么方向
│  (设计)      │  写人设、定技能、配工具
└──────┬──────┘
       ▼
┌─────────────┐
│  Do          │  执行：修改配置、添加技能
│  (实施)      │  重启 DSH、测试对话
└──────┬──────┘
       ▼
┌─────────────┐
│  Check       │  检查：分身表现是否符合预期
│  (评估)      │  记录问题、收集反馈
└──────┬──────┘
       ▼
┌─────────────┐
│  Act         │  行动：根据反馈调整
│  (改进)      │  回到 Plan 优化人设/技能
└──────┬──────┘
       │
       └────────── 循环 ──────────→
```

### 评估维度

| 维度 | 好 | 不好 | 改进方法 |
|------|----|------|---------|
| **身份认同** | 知道自己是罗拉分身 | 答非所问、角色混乱 | 优化身份层人设 |
| **表达风格** | 直接、结构化 | 啰嗦、模糊 | 优化表达层指令 |
| **工具使用** | 主动调用工具 | 全凭知识回答 | 优化工具说明 + 加技能 |
| **记忆利用** | 主动查记忆 | 忘了之前的事 | 优化 memory_read 提示 |
| **访客处理** | 能区分主人/访客 | 一视同仁 | 优化访客指令 |

## 七、总结

```
数字分身 = 好的模型 + 清晰的人设 + 合适的工具 + 持续优化
               ↑            ↑            ↑            ↑
             基础层       身份+表达     行为层      PDCA循环
```

目前罗拉的数字分身已经在基础层和行为层有了较好的基础（模型、MCP 工具、记忆系统、访客隔离），接下来的重点是 **身份层和表达层的精细化**，以及 **技能体系的建设**。
