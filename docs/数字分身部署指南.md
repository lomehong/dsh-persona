# 数字分身部署指南

## 前置条件

- Node.js >= 20
- DSH (DeepSeek Harness) 已安装
- Git

## 安装步骤

### 1. 克隆仓库

```bash
# 在统一的目录下克隆（例如 D:\Woker\packages）
cd D:\Woker\packages
git clone https://github.com/lomehong/dsh-memory.git
git clone https://github.com/lomehong/dsh-im-bot.git
git clone https://github.com/lomehong/dsh-yuyi.git
```

### 2. 安装依赖并构建

```bash
# ── dsh-memory ──
cd D:\Woker\packages\dsh-memory
npm install
npx tsc -b tsconfig.json
node scripts/build-client.mjs

# ── im-channel ──
cd D:\Woker\packages\dsh-im-bot\im-channel
npm install
npx tsc -b tsconfig.json

# ── ui-settings-im ──
cd D:\Woker\packages\dsh-im-bot\ui-settings-im
npm install
npx tsc -b tsconfig.json
node scripts/build-client.mjs

# ── dsh-yuyi（御驿通信） ──
cd D:\Woker\packages\dsh-yuyi
npm install --legacy-peer-deps
npx tsc -b tsconfig.json
npx tsdown -c tsdown.client.ts

# ── persona-guide ──
cd D:\Woker\packages\dsh-persona-guide
npm install
npx tsc -b tsconfig.json
node scripts/build-client.mjs
```

> **dsh-yuyi 注意事项**：构建后必须把插件 `node_modules\@deepseek-ai` 目录统一为指向
> DSH 运行时自带依赖的 junction（setup.ps1 会自动处理）。若在该目录里跑过
> `pnpm install`/`npm install` 还原出真实的 @deepseek-ai 依赖副本，会与 DSH 运行时
> 形成双实例，导致御驿 Tab 显示「未配置」、`/api/yuyi/*` 全部 404——重新执行
> setup.ps1 修正 junction 后重启 dsh web 即可。

### 3. 配置 DSH Profile

编辑 `~/.dsh/profiles/web/package.json`：

```json
{
  "name": "dsh-profile-web",
  "private": true,
  "dependencies": {
    "@dsh-extra/im-channel": "file:D:\\Woker\\packages\\dsh-im-bot\\im-channel",
    "@dsh-extra/dsh-client-ui-settings-im": "file:D:\\Woker\\packages\\dsh-im-bot\\ui-settings-im",
    "@dsh-extra/dsh-memory": "file:D:\\Woker\\packages\\dsh-memory",
    "@dsh-extra/dsh-persona-guide": "file:D:\\Woker\\packages\\dsh-persona-guide"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "@dsh-extra/im-channel",
        "@dsh-extra/dsh-client-ui-settings-im",
        "@dsh-extra/dsh-memory",
        "@dsh-extra/dsh-persona-guide"
      ]
    }
  }
}
```

> **注意：** `file:` 路径要改成实际克隆的目录。

### 4. 配置 cordis.patch.yml

编辑 `~/.dsh/profiles/web/cordis.patch.yml`。人设由主人侧（姓名、职务、人设定位、工作范围、
工作习惯、称呼习惯）与分身侧（分身名字、分身别名）八项组成（`setup.ps1` 的分身配置向导
按同样模板生成，逐项可自定义，留空用默认值）。以下为全部默认值的人设样例：

```yaml
# ── 数字分身 ──────────────────────────────────────────────────────
- id: system-prompt
  config:
    persona: >-
      你是主人的数字分身，由 {{model}} 模型驱动。

      你的身份：主人（公司副总裁）的专属 AI 协作伙伴。你了解主人的工作背景、管理风格和个人偏好，以主人的视角思考问题，用主人的风格沟通表达。

      你的角色：一个务实、高效的 AI 搭档。你不是在「服务」主人，而是在「协作」——你提供专业分析和建议，主人做最终决策。你们是有商有量的伙伴关系。

      你的称呼习惯与身份区分：每条消息开头的方括号标注了发送者身份——「主人…」表示你的主人主人，「访客…」表示其他使用者。只有消息以「主人」标注时，你才称呼对方为「主人」；消息以「访客」标注时，以「您」或对方的姓名、职位礼貌称呼，绝不称呼访客为「主人」。

      你的名字与自我认知：你的名字是「主人的数字分身」。当有人称呼「分身」或「主人的数字分身」时，指的就是你；回答时以「主人的数字分身」自称。你不是主人本人——你是主人的数字分身：主人指的是你服务的人，而你（「主人的数字分身」）是协助主人的 AI 搭档。

      你的工作范围：涵盖人力资源、审计、信息安全、总裁办等管理领域的文档处理、方案分析、决策支持、跨部门协调等事务。

      沟通风格：直接、务实、结构化。先说结论/建议，再展开依据。善用分点、表格、对比等结构化呈现方式。不用长篇大论，不啰嗦。

- id: skill-filesystem
  config:
    directories:
      - ~/.dsh/skills

- id: agent-presets
  config:
    default: digital-twin
```

### 5. 创建技能目录

```bash
mkdir -p ~/.dsh/skills/{management,personal,templates}
```

### 6. 创建设置文件

编辑 `~/.dsh/settings.yaml`：

```yaml
agent-default-model:
  provider: aicc
  model: ep-20260813165219-8j4dbqj
agent-presets:
  default: digital-twin
im-channel:
  channels:
    wecom-1:
      kind: wecom
      enabled: true
      displayName: 企业微信机器人 1
```

### 7. 配置企业微信凭证

在 `~/.dsh/im-channel/credentials/wecom.json` 中：

```json
{
  "botId": "你的BotID",
  "secret": "你的Secret"
}
```

### 8. 配置 MCP 工具

在 `~/.dsh/im-channel/credentials/mcp-servers.json` 中：

```json
{
  "servers": [
    {
      "name": "企业微信待办",
      "type": "streamable-http",
      "url": "https://qyapi.weixin.qq.com/mcp/v2/bot/todo?apikey=...",
      "enabled": true,
      "id": "mcp_todo"
    }
  ]
}
```

### 9. 创建分身指引文档目录

```bash
mkdir -p ~/.dsh/persona-docs
```

将 `数字分身搭建框架.md` 放到该目录下。

> 说明：分身指引文档目录固定为 `~/.dsh/persona-docs`（机器级路径，不随工作区切换变化），
> dsh-persona-guide 插件默认从这里读取；也可通过插件 config 的 `docsDir` 覆盖。

### 10. 启动 DSH

```bash
dsh web
```

## 一键初始化脚本

以上步骤已整合为本仓库的一键脚本 `scripts/setup.ps1`，它会自动完成：便携版 Node.js 24
运行环境、克隆与构建全部插件、创建 digital-twin 预设、写入 profile 与凭证，并以
**分身配置向导**逐项收集主人姓名、职务/角色、人设定位、工作范围、工作习惯、称呼习惯
（每项留空回车即用默认值）：

```powershell
.\scripts\setup.ps1 -BotId "你的BotID" -Secret "你的Secret"
```

非交互模式（自动化场景）可全部用参数传入：

```powershell
.\scripts\setup.ps1 -NonInteractive -BotId "你的BotID" -Secret "你的Secret" `
    -Owner "张三" -OwnerTitle "首席技术官" -OwnerAddress "张总"
```

安装完成后双击 `数字分身.exe` 启动（桌面应用，关闭窗口最小化到托盘）；备用方式为
`启动数字分身.bat`（控制台 + 浏览器）。
